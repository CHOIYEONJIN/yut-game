# 웹 윷놀이 1단계 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한 화면에서 2~4명이 번갈아 하는 윷놀이를, 명세서 규칙대로 끝까지 플레이할 수 있게 만든다.

**Architecture:** 규칙은 `src/rules/`의 순수 함수(React를 모름, 상태를 직접 바꾸지 않고 새 상태를 돌려줌)로 만들고 Vitest로 검사한다. 화면은 `src/ui/`의 React 컴포넌트가 규칙 함수만 불러서 그린다. 게임 상태는 JSON으로 바꿀 수 있는 평범한 객체 하나다.

**Tech Stack:** Vite, React, JavaScript (TypeScript 아님), Vitest, 일반 CSS

**Spec:** `docs/superpowers/specs/2026-11-25-yut-stage1-design.md` (원본 요구사항: `CLAUDE.md`)

## Global Constraints

- 모든 코드에 **한국어 주석**을 단다. 초보자가 읽을 수 있게 "왜"를 설명한다.
- `src/rules/` 안의 파일은 React, DOM, `window`를 절대 사용하지 않는다.
- 규칙 함수는 인자로 받은 상태를 바꾸지 않는다 (`structuredClone` 후 수정해서 반환).
- Vite 설정에 `base: './'` (게임 모음 사이트의 어느 폴더에 넣어도 동작해야 함).
- 명세서에 없는 기능은 추가하지 않는다 (효과음, 애니메이션 필수 아님, 저장, undo, AI 없음).
- 각 Task가 끝나 테스트가 통과하면 커밋한다. 커밋 메시지는 한국어, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- 결과 이름(코드 값): `'backdo' | 'do' | 'gae' | 'geol' | 'yut' | 'mo'`, 칸 수 `-1, 1, 2, 3, 4, 5`. 화면 표시는 `빽도, 도, 개, 걸, 윷, 모`.
- 플레이어 색 순서: 빨강 `#e53935`, 파랑 `#1e88e5`, 초록 `#43a047`, 노랑 `#fdd835`.

## Review Focus

1. **결과 순서에 따라 쓸 수 있게 되는 경우**: [빽도, 개]이고 판에 말이 없으면, 처음엔 개만 쓸 수 있고 개로 말을 꺼낸 뒤엔 빽도를 쓸 수 있어야 한다 → Task 5 테스트.
2. **잡은 결과가 모음의 마지막일 때**: 모음이 비어도 턴이 끝나지 않고 던지기 단계로 가야 한다. 거기서 윷이 나오면 또 던진다 → Task 6 테스트.
3. **완주 대기 칸으로 내 말이 합류**: 0번에서 업힌 뒤, 같은 턴 남은 결과 하나로 둘이 함께 완주한다 → Task 6 테스트.
4. **모서리에서 빽도**: 5번 칸 말에 빽도를 쓰면 길 선택 없이 이동이 하나만 나와야 한다 → Task 5 테스트.
5. **게임 종료 후/잘못된 단계의 클릭**: `phase`가 `'over'`이거나 맞지 않는 단계에서 `throwYut`/`applyMove`를 부르면 상태가 바뀌지 않아야 한다. 화면은 단계에 맞는 버튼만 보여준다 → Task 4, Task 6 테스트.

## 게임 상태 모양 (모든 Task가 공유)

```js
{
  players: [{ name: '철수', color: '#e53935' }, ...],   // 2~4명
  pieces: [                                             // 플레이어마다 4개, id 0부터 순서대로
    { id: 0, owner: 0, status: 'home', pos: null, history: [] },
    // status: 'home'(출발 전) | 'board'(판 위) | 'waiting'(완주 대기, pos 0) | 'done'(완주)

  ],

  phase: 'throw',        // 'throw' | 'move' | 'over'
  throwsLeft: 1,         // 던지기 단계에서 더 던질 횟수
  pool: [],              // 모인 결과 목록, 예: ['mo', 'gae']

  winner: null,          // 우승 플레이어 번호
  message: ''            // 화면에 보여줄 안내 (예: '쓸 수 있는 결과가 없어 턴이 넘어갑니다')
}
```

### Task 2: 윷판 이동 규칙 (`board.js`)

**Files:**
- Create: `src/rules/board.js`, `src/rules/__tests__/board.test.js`
- Delete: `src/rules/__tests__/smoke.test.js`

**Interfaces:**
- Produces:
  - `START = 0`, `CENTER = 22`, `CORNERS = [5, 10]`
  - `routeOptions(pos) → Array<'shortcut' | 'outer' | null>`: 5, 10이면 `['shortcut', 'outer']`, 그 외 `[null]`
  - `walk(start, steps, route) → { path: number[], finished: boolean }`: `start`에서 `steps`(1 이상)칸 앞으로. `path`는 지나간 칸들(시작 칸 제외, 마지막이 도착 칸). 걷는 도중 0에 도착했는데 걸음이 남아 있으면 `finished: true`이고 거기서 멈춘다(`path`의 마지막은 0).
  - `remainingSteps(pos, route) → number`: `pos`에서 0까지 걸음 수

한 칸 이동 규칙 (설계 문서 6장):
- 이동 시작 칸이 5: `shortcut` → 20, `outer` → 6. 시작 칸이 10: `shortcut` → 25, `outer` → 11.
- 22: 시작 칸이면 27, 바로 전이 21이면 23, 바로 전이 26이면 27.
- 20→21→22, 23→24→15, 25→26→22, 27→28→0, 바깥 p→p+1 (19→0). 시작이 아닌 5, 10은 바깥으로 간다.

- [ ] **Step 1: 실패하는 테스트 작성**

### Task 6: 잡기, 업기, 턴 진행, 승리 (`game.js` 3부)

**Files:**
- Modify: `src/rules/game.js`, `src/rules/__tests__/game.test.js`

**Interfaces:**
- Consumes: Task 5의 `applyMove`, `getLegalMoves`
- Produces:
  - `applyMove`가 추가로 처리:
    1. **잡기:** 도착 칸(0 포함)에 다른 플레이어의 `board`/`waiting` 말이 있으면 모두 `{status:'home', pos:null, history:[]}`로 되돌리고 `throwsLeft += 1`. 완주(`finishes`)는 잡지 않는다.
