# 윷놀이 2단계 (대기실 + 온라인) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서로 다른 기기의 2~4명이 빠른대전(빈자리는 컴퓨터) 또는 친선대전(초대코드)으로 만나 1단계 규칙 그대로 한 판을 끝까지 한다.

**Architecture:** `server/`의 Node.js + Socket.IO 서버가 유일한 심판이다. 화면은 행동(던지기/이동)만 보내고, 서버가 `src/rules/`의 `throwYut`/`applyMove`로 판정해 새 상태를 방 전체에 보낸다. 서버 로직은 Socket.IO를 모르는 순수 모듈(`match.js`, `matchmaking.js`, `rooms.js`)과, 이들을 소켓에 잇는 `hub.js`로 나눈다.

**Tech Stack:** Node 24, Socket.IO 4.8.x (`socket.io`, `socket.io-client`), React 19, Vite 8, Vitest 5 (가짜 시계 `vi.useFakeTimers`).

**Spec:** `docs/superpowers/specs/2026-11-28-yut-stage2-design.md`

## Global Constraints

- 규칙은 `src/rules/` 한 벌만. 서버는 `../src/rules/*.js`를 import한다. 규칙 파일의 기존 함수 동작을 바꾸지 않는다 (새 파일 `bot.js`만 추가).
- 코드에 한국어 주석. JavaScript (TypeScript 아님). 일반 CSS.
- 시간 값: 빠른대전 대기 `30000`ms, 사람 한 동작 `30000`ms, 컴퓨터 생각 `1000`ms, 윷 굴림 `900`ms (화면 `ROLL_MS`와 같음). 모두 함수 옵션으로 바꿀 수 있게 하고 기본값을 이 숫자로 한다.
- 최대 4명, 친선대전 시작은 2명 이상 + 방장만.
- 컴퓨터 이름: `컴퓨터1`, `컴퓨터2`, `컴퓨터3` (빈자리 순서대로).
- 초대코드: 4글자, 글자 모음 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (O, 0, I, 1 제외).
- 화면 문구(정확히): `움직일 수 있는 말이 없습니다.`(기존), `자동 진행 중`, `서버를 깨우는 중…`, `다른 창에서 접속했습니다`, `진행 중인 게임이 있어요`, `이어하기`, `나가기`, `게임 나가기`, `컴퓨터와 바로 하기`, `빠른대전`, `친선대전`, `초대코드 발급`, `초대코드 입장`.
- 1단계 "한 화면에서 번갈아 하기"는 입구에서 뺀다 (`SetupScreen.jsx` 삭제). 규칙 코드와 테스트는 그대로 둔다.
- 서버 주소: 화면은 `import.meta.env.VITE_SERVER_URL`, 없으면 `http://localhost:3001`. 서버는 `PORT`(기본 3001), 허용 출처 `ALLOWED_ORIGIN`(기본 `*`).
- 커밋 메시지는 한국어, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. 작업 브랜치 `stage2`.

## Review Focus

1. 혼자일 때만 보이는 "컴퓨터와 바로 하기"를, 두 번째 사람이 막 들어온 순간에 누름 → 서버는 줄에 사람이 2명 이상이면 무시하고 30초 세기를 계속한다. (Task 3 테스트)
2. 시간 초과나 끊김으로 컴퓨터가 그 차례를 맡은 뒤 본인이 행동을 보냄 (늦게 도착한 클릭) → 무시한다. (Task 2 테스트)
3. 같은 이동/던지기를 빠르게 두 번 보냄 (두 번 클릭, 네트워크 재전송) → 두 번째는 무시하고 차례가 꼬이지 않는다. (Task 2 테스트)
4. 줄이나 친선대전 방에 있는 사람이 같은 브라우저에서 새 창을 엶 → 새 창이 이어받되, 이전 창이 끊겼다고 줄/방에서 빠지면 안 된다. (Task 5 테스트)
5. 게임이 끝나거나 완전히 나간 뒤 → 그 사람은 바로 새 빠른대전/친선대전을 할 수 있고, 다시 접속해도 "진행 중인 게임이 있어요"가 뜨지 않는다. (Task 5 테스트)

### Task 2: 서버의 게임 한 판 (`match.js`)

**Files:**
- Create: `server/match.js`
- Test: `server/__tests__/match.test.js`
- Modify: `package.json` (devDependencies 아님, dependencies에 `socket.io`, `socket.io-client` 추가: `npm install socket.io@4.8 socket.io-client@4.8`)

**Interfaces:**
- Consumes: `createGame`, `throwYut`, `applyMove` (`game.js`), `botStep` (Task 1)
- Produces:

```js
createMatch({
  seats,            // [{ playerId: string|null, name: string, kind: 'human'|'bot' }] 2~4개, 순서 = 플레이어 번호
  random = Math.random,
  turnMs = 30000, botDelayMs = 1000, rollMs = 900,
  onUpdate,         // (view) => void  상태가 바뀔 때마다
  onEnd,            // ({ winner: number|null }) => void  우승자 또는 사람이 모두 없어 끝남(null). 한 번만 호출
}) -> {
  start(),                         // 첫 onUpdate + 첫 차례 예약
  act(playerId, action) -> boolean,// action: { type: 'throw' } | { type: 'move', move: { resultIndex, pieceId, route } }
  setConnected(playerId, connected: boolean),
  leave(playerId),                 // 완전히 나감
  seatOf(playerId) -> number,      // 나가지 않은 사람 자리 번호, 없으면 -1
  view() -> {
    state,                         // 규칙의 게임 상태 그대로
    seats: [{ name, kind, status }], // status: 'playing' | 'away'(끊김) | 'left'(완전히 나감) | 'bot'
    auto: boolean,                 // 지금 차례를 컴퓨터가 대신 두는 중인지 (사람 자리인데)
    turnMsLeft: number|null,       // 사람이 직접 둘 때 이 동작의 남은 시간, 아니면 null
    throwSeq: number,              // 던질 때마다 1 증가 (화면 굴림 애니메이션용)
  },
  stop(),                          // 모든 예약 취소
}
```

규칙 (스펙 6·7장):
- 지금 차례를 "컴퓨터가 둔다" = 자리가 `bot` 또는 `left` 또는 `away`, 또는 이번 차례에 `autoThisTurn`이 켜짐. `autoThisTurn`은 시간 초과나 끊김으로 켜지고, `state.current`가 바뀔 때만 꺼진다 (다시 접속해도 그 차례는 컴퓨터가 마저).
- 컴퓨터가 둘 때: `botDelayMs` 뒤 `botStep`. 방금 던졌으면 `rollMs + botDelayMs` 뒤.
- 사람이 둘 때: `turnMs` 뒤(방금 던졌으면 `rollMs + turnMs` 뒤) 시간 초과 → `autoThisTurn = true`, 컴퓨터 진행 예약. 사람이 행동하면 시간을 다시 센다.
- `act`는 자기 차례가 아니거나, 지금 컴퓨터가 두는 중이거나, 규칙 함수가 상태를 그대로 돌려주면(할 수 없는 행동) `false`이고 아무것도 바꾸지 않는다.
- `phase === 'over'`면 마지막 `onUpdate` 후 `onEnd({ winner })`, 예약 모두 취소.
- 사람 자리 중 `playing`이 하나도 없으면 `onEnd({ winner: null })`, 예약 모두 취소.

```js

test('컴퓨터 차례는 1초 뒤 자동으로 둔다')                        // a 다음 컴퓨터 차례: advanceTimersByTime(999) 변화 없음, (1) 뒤 throwSeq 증가

                                                                 // setConnected('a',false) → seats[0].status 'away', auto true;
                                                                 // setConnected('a',true) 같은 차례 → act false; 다음 a 차례 → act true
test('완전히 나가면 다시 접속해도 끝까지 컴퓨터가 둔다')           // leave('a') → status 'left', seatOf('a') === -1, setConnected('a',true) 무효
test('사람이 모두 끊기거나 나가면 onEnd({ winner: null })이 한 번 불린다')
test('우승자가 나오면 마지막 상태를 보낸 뒤 onEnd({ winner })')     // 말 3개 done + 완주 대기 1개로 꾸민 상태에서 도 → winner 0
```

### Task 4: 친선대전 방 (`rooms.js`)

**Files:**
- Create: `server/rooms.js`
- Test: `server/__tests__/rooms.test.js`

**Interfaces:**
- Produces:

```js
createRooms({ startMatch /* (code, seats) => void, seats는 모두 'human' */, random = Math.random }) -> {
  create({ playerId, name }) -> code,            // 만든 사람이 방장
  join(code, { playerId, name }) -> { ok: true } | { ok: false, error: 'NOT_FOUND' | 'FULL' | 'STARTED' },
  leave(playerId) -> code|null,                  // 시작 전 방에서만 의미 있음. 방장이면 다음 사람이 방장, 마지막이면 방 삭제

  members(code) -> string[],
  view(code) -> { code, players: string[], hostIndex: number, started: boolean },
```

| 화면→서버 | `game:action` | `{ action }` (Task 2의 action) |

| 서버→화면 | `room:error` | `{ error }` (Task 4 에러 코드) |
| 서버→화면 | `game` | `{ ...match view, mySeat }` |
| 서버→화면 | `game:over` | `{ winner: { name, color } \| null }` |
| 서버→화면 | `resume:offer` | 없음 (진행 중인 게임이 있어요 → 이어하기/나가기) |
| 서버→화면 | `replaced` | 없음 (다른 창에서 접속했습니다) |
