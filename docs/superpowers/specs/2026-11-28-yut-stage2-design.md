# 웹 윷놀이 2단계 설계 문서 (대기실 + 온라인 멀티플레이)

작성일: 2026-11-28
원본 요구사항: 프로젝트 루트의 `CLAUDE.md`, 1단계 설계 문서(`2026-11-25-yut-stage1-design.md`), 2026-11-28 대화

## 1. 목적과 이유

- 서로 다른 기기(폰, 노트북)에 있는 2~4명이 인터넷으로 같은 윷놀이 판을 함께 한다.
- 최종 목표는 팀원들이 만든 게임을 모은 "미니게임천국" 같은 포털이다.
  포털에는 게임 장소가 있는 맵이 있고, 윷놀이 장소로 가면 "윷놀이를 플레이 하시겠습니까?"가 뜨고,
  "예"를 누르면 **윷놀이 방 입구**로 들어온다. 이번 2단계는 이 "윷놀이 방 입구"부터 만든다.
- 사용자가 적은 초반에도 (1) 사람끼리 만날 수 있고 (2) 혼자 와도 놀 수 있어야 한다.
- 개발자는 코딩 초보다. 구조는 단순하게, 코드에는 한국어 주석을 단다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 윷놀이 방 입구에서 닉네임을 정하고 **빠른대전** 또는 **친선대전**을 고를 수 있다.
- 빠른대전: 모르는 사람과 자동으로 짝지어지고, 빈자리는 컴퓨터가 채운다 (아래 4장).
- 친선대전: 초대코드를 만들어 친구를 부르거나, 받은 초대코드로 친구 방에 들어간다.
- 서로 다른 기기에서 접속한 2~4명이 1단계 규칙 그대로 한 판을 끝까지 할 수 있다.
- 게임 중 누가 접속이 끊겨도 남은 사람들은 게임을 끝까지 할 수 있다.
- 플레이 링크(GitHub Pages)에서 그대로 접속해 플레이할 수 있다.

**비목표 (이번에 만들지 않는 것)**
- 포털 맵, "플레이 하시겠습니까?" 창 (포털 프로젝트에서 만든다)
- 로그인/계정, 전적·승률 저장 (3단계)
- 진행 중인 게임의 컴퓨터 자리에 새 사람이 끼어들기 (사용자가 늘면 나중에 검토)
- 친선대전에 컴퓨터 넣기, 채팅, 구경하기(관전), 효과음, 모바일 최적화
- 한 화면에서 번갈아 하기(1단계 방식)를 입구에 보여 주기 (입구에서 뺀다. 규칙 코드는 그대로 남는다)

**실패로 보는 것 (기능은 돌아가도 실패)**
- 규칙 판정을 각자의 브라우저가 해서, 화면마다 판이 달라지거나 조작으로 규칙을 어길 수 있는 경우
- 서버용으로 규칙 코드를 따로 복사해 두 벌이 생기는 경우 (규칙은 `src/rules/` 한 벌만)
- 거의 같은 시간에 들어온 두 사람이 각자 따로 컴퓨터와 하게 되는 경우 (4장 방식이 막아야 한다)
- 한 사람이 끊겨서 나머지 사람들의 게임이 멈추는 경우

## 3. 확정된 결정 사항

| 항목 | 결정 | 결정한 사람 |
|---|---|---|
| 입구 구성 | 빠른대전 / 친선대전. 친선대전은 초대코드 발급 / 초대코드 입장 | 사용자 |
| 빠른대전 인원 | 사람이 모자라면 컴퓨터로 채워서 한다 | 사용자 |
| 빠른대전 시작 방식 | C안: 사람 2명 이상이면 30초 뒤 빈자리를 컴퓨터로 채워 4명으로 시작(4명이 차면 바로 시작). 혼자면 자동 시작하지 않고, "컴퓨터와 바로 하기" 버튼으로 직접 시작 | 사용자 (C안 선택) |
| 접속 끊김 | 서버가 몇 초마다 접속을 확인하고, 대답이 없으면 끊긴 것으로 본다. 바로 "자동 진행 중"을 표시하고 그 사람 차례를 컴퓨터가 대신 둔다. 다시 접속하면 표시가 사라지고, 컴퓨터가 두던 차례는 컴퓨터가 마저 끝내고 다음 차례부터 본인이 둔다 | 사용자 (다른 세션에서 승인) |
| 사람이 모두 나감 | 컴퓨터만 남으면 그 게임을 끝낸다 | 제안 → 사용자 승인 |
| 이름 | B안: 들어올 때 닉네임만 입력, 그 기기에 기억. 이름을 다루는 코드는 한 곳에 모아 나중에 포털 로그인으로 바꾸기 쉽게 | 사용자 (B안 선택) |
| 서버 방식 | A안: 직접 만든 Node.js 게임 서버가 심판을 맡는다 | 사용자 (A안 선택) |
| 컴퓨터 실력 | 잡기 → 완주 → 가장 멀리 가는 수 순서로 고른다. 두기 전 약 1초 기다린다 | 제안 (사용자가 반대하지 않음) |
| 친선대전 방 | 방장이 초대코드를 받는다. 들어온 사람 목록을 보여 주고, 2명 이상이면 방장이 "시작". 최대 4명. 컴퓨터 없음 | 제안 (사용자가 반대하지 않음) |
| 자리 비움 (접속은 됨) | 한 동작(던지기, 말 옮기기)마다 30초. 시간이 끝나면 그 차례는 컴퓨터가 마저 두고, 다음 차례부터 다시 본인이 둔다 | 사용자 |
| 게임 중 나가기 | "게임 나가기" 버튼으로 완전히 나가면 그 자리는 끝까지 컴퓨터가 둔다. 창만 닫았다 다시 오면 "진행 중인 게임이 있어요: 이어하기 / 나가기"를 묻는다 | 사용자 |
| 창 여러 개 | 브라우저 하나 = 한 사람. 새 창이 이어받고 이전 창에는 "다른 창에서 접속했습니다" 표시 | 구현자 판단 |
| 친선대전 방장이 나감 (시작 전) | 다음으로 들어온 사람이 방장이 된다. 아무도 없으면 방을 지운다 | 구현자 판단 |

## 4. 빠른대전 흐름

```
[빠른대전 찾는 중…]
 ● 연진 (나)   ○ 빈자리   ○ 빈자리   ○ 빈자리
 [컴퓨터와 바로 하기]   [나가기]
```

1. 빠른대전을 누르면 서버의 "기다리는 줄"에 들어간다.
2. 줄에 사람이 1명뿐: 자동으로 시작하지 않는다. "컴퓨터와 바로 하기"를 누르면 그 사람 + 컴퓨터 3명으로 바로 시작한다.
3. 줄에 사람이 2명 이상: 30초를 세기 시작한다 (화면에 남은 초 표시).
   - 그사이 4명이 차면 바로 시작한다.
   - 30초가 끝나면 빈자리를 컴퓨터로 채워 4명으로 시작한다.
   - 세는 동안 사람이 나가서 1명이 되면 세기를 멈추고 2번 상태로 돌아간다.
4. 기다리는 사람은 언제든 "나가기"로 줄에서 빠질 수 있다.
5. 줄은 하나다. 게임이 시작되면 그 사람들은 줄에서 빠지고, 새로 온 사람은 새 줄을 만든다.

## 5. 친선대전 흐름

```
[친선대전]                         [방: 초대코드 4F7K]
 [초대코드 발급]                     ● 연진 (방장)
 [초대코드 입장: ____ ]              ● 민수
                                    ○ 빈자리  ○ 빈자리
                                    [시작] (방장만, 2명 이상일 때)  [나가기]
```

- 초대코드 발급: 서버가 새 방과 짧은 코드(헷갈리는 글자 O/0, I/1 제외)를 만든다. 만든 사람이 방장.
- 초대코드 입장: 코드를 입력하면 그 방에 들어간다. 없는 코드, 꽉 찬 방(4명), 이미 시작한 방이면 이유를 알려 준다.
- 들어온 순서대로 플레이어 1~4번(색: 빨강, 파랑, 초록, 노랑)이 된다.

## 6. 게임 중

- 게임 화면은 1단계 화면(윷판, 대기 공간, 윷가락, 결과 고르기)을 그대로 쓴다.
- **내 차례일 때만** 던지기·말 고르기가 눌린다. 다른 사람 차례에는 "○○ 차례" 표시와 함께 진행 모습만 보인다.
- 컴퓨터 자리와 "자동 진행 중"인 자리에는 이름 옆에 표시를 붙인다 (예: 🤖, "자동 진행 중").
- 사람 차례에는 한 동작(던지기 한 번, 말 옮기기 한 번)마다 30초가 주어지고 남은 초가 모두에게 보인다.
  동작을 하면 다시 30초부터 센다. 시간이 끝나면 그 차례의 남은 동작은 컴퓨터가 두고, 다음 차례부터 다시 본인이 둔다.
  (윷가락이 굴러가는 시간, 컴퓨터가 생각하는 시간은 세지 않는다)
- 게임 화면에 "게임 나가기" 버튼이 있다 (누르면 정말 나갈지 한 번 묻는다).
- 누가 윷을 던지면 모든 화면에서 윷가락이 굴러가는 움직임이 보인다.
- 게임이 끝나면 결과 화면(우승자 표시) → "입구로" 버튼으로 윷놀이 방 입구로 돌아간다.

## 7. 접속 끊김 (3장 결정을 자세히)

- 서버는 몇 초마다 각 기기에 "살아 있니?"를 보내고, 대답이 없으면 끊긴 것으로 본다.
  (사용할 도구 Socket.IO가 이 확인을 기본으로 해 준다. 간격은 구현자 판단, 약 10~20초 안에 알아채는 정도)
- 끊긴 사람: 모두의 화면에 "자동 진행 중" 표시. 그 사람 차례는 컴퓨터가 대신 둔다.
- 다시 접속: 같은 기기(같은 플레이어 번호표)로 들어오면 원래 자리를 되찾고 표시가 사라진다.
  컴퓨터가 두던 차례는 컴퓨터가 마저 끝내고, 다음 차례부터 본인이 둔다.
- 끊긴 사람이 사이트를 다시 열면 바로 끌고 들어가지 않고 "진행 중인 게임이 있어요: 이어하기 / 나가기"를 묻는다.
  "이어하기"면 원래 자리로, "나가기"면 아래 "완전히 나감"과 같다.
- **완전히 나감** ("게임 나가기" 버튼, 또는 위 질문에서 "나가기"): 그 자리는 다시 되찾을 수 없고 끝까지 컴퓨터가 둔다.
  그 사람은 그 게임과의 연결이 풀려서 바로 새 게임을 할 수 있다.
- 자리 상태는 세 가지다: 사람이 두는 중 / 끊겨서 자동 진행 중(돌아올 수 있음) / 완전히 나감(컴퓨터가 끝까지).
- 접속한 사람이 아무도 없으면(모두 끊겼거나 완전히 나감) 그 게임은 끝내고 지운다.
- 게임 시작 전(줄, 친선대전 방)에서 끊긴 사람은 그냥 나간 것으로 본다.

## 8. 서버 방식 (검토한 접근법)

서버가 해야 할 일 중 "30초 세기", "컴퓨터가 두기", "끊긴 사람 대신 두기"는
누군가 계속 켜져 있으면서 해야 한다. 이것이 선택을 갈랐다.

| 방식 | 장점 | 단점 | 결과 |
|---|---|---|---|
| **A. 직접 만든 Node.js 게임 서버** | `src/rules/`를 서버에서 그대로 쓴다. 짝짓기·시간 세기·컴퓨터를 한 곳에서 자연스럽게 처리. 자료가 많아 배우기 쉽다 | 서버를 올릴 곳이 필요. 무료 호스팅은 오래 안 쓰면 잠들어 첫 접속이 30초~1분 느릴 수 있다 | **사용자 선택** |
| B. 클라우드플레어 Durable Objects | A처럼 심판 방식, 잠들지 않음, 무료 양이 넉넉한 편 | 개념이 낯설고 처음 설정이 많다. 자료가 적다 | 선택 안 함 (나중에 옮길 수 있게 A를 만든다) |
| C. Supabase/Firebase 데이터베이스만 공유 | 서버 코드가 거의 없다 | 심판이 없어 누군가의 브라우저가 시간 세기·컴퓨터를 맡아야 하고, 그 사람이 나가면 멈춘다. 4장·7장과 맞지 않는다 | 선택 안 함 |

## 9. 구조

```
src/rules/        1단계 규칙 (그대로). 서버와 화면이 함께 쓴다
src/rules/bot.js  (새로) 컴퓨터가 둘 수를 고르는 순수 함수
server/           (새로) Node.js 게임 서버
  index.js          서버 시작, 접속 받기
  matchmaking.js    빠른대전 줄과 30초 세기
  rooms.js          친선대전 방, 초대코드
  match.js          게임 한 판: 행동 받기 → 규칙 함수로 판정 → 모두에게 새 상태 보내기, 컴퓨터/자동 진행 차례 처리
src/net/          (새로) 화면 쪽 접속 코드
  identity.js       닉네임과 플레이어 번호표 (이름을 다루는 유일한 곳, 나중에 포털 로그인으로 교체)
  connection.js     서버와 주고받기
src/ui/           입구, 빠른대전 대기, 친선대전 방 화면 추가. GameScreen은 온라인용으로 조금 고친다
```

**심판은 서버 하나다.**
- 화면은 "던지기", "이 이동 하기" 같은 **행동만** 서버에 보낸다.
- 서버가 `throwYut`/`applyMove`로 판정하고, 새 게임 상태를 그 방의 모두에게 보낸다.
- 윷 던지기의 무작위도 서버에서 정한다.
- 규칙 함수가 상태를 그대로 돌려주면(할 수 없는 행동) 무시한다. 자기 차례가 아닌 사람의 행동도 무시한다.

**누가 어느 자리인지는 규칙 밖에서 관리한다.**
- 규칙의 게임 상태(`players`, `pieces` …)는 바꾸지 않는다.
- 서버의 방 정보에 자리별로 `{ 플레이어 번호표, 이름, 사람/컴퓨터, 접속 중 여부 }`를 따로 둔다.

**컴퓨터(`bot.js`)**
- `chooseMove(state)`: `getLegalMoves` 중에서
  1. 상대 말을 잡는 수
  2. 없으면 완주하는 수
  3. 없으면 가장 멀리 가는 수(이동 뒤 완주까지 남은 칸이 가장 적은 수)
  
  를 고른다. 같으면 앞의 것.
- 던지기 단계면 던진다. 서버가 약 1초 기다렸다가 실행한다.

**이름과 번호표**
- 처음 들어올 때 닉네임을 입력받고, 무작위 플레이어 번호표(긴 무작위 글자)를 만들어 그 기기(브라우저 저장소)에 기억한다.
- 서버는 번호표로 "다시 접속한 같은 사람"을 알아본다.
- 같은 브라우저의 창들은 번호표를 함께 쓰므로 한 사람이다. 같은 번호표로 새 창이 접속하면 새 창이 이어받고, 이전 창은 끊고 안내를 띄운다.
- 개발·테스트 때만 주소에 설정(예: `?player=2`)을 붙여 창마다 다른 번호표를 쓰게 한다. 실제 플레이 링크에서는 이 설정이 동작하지 않게 한다.

**서버 주소**
- 화면(GitHub Pages)이 접속할 서버 주소는 빌드할 때 설정값으로 넣는다. 개발 중에는 내 컴퓨터의 서버로 접속한다.

**저장**
- 2단계는 진행 중인 방과 게임을 서버 메모리에만 둔다. 서버가 다시 켜지면 진행 중이던 게임은 사라진다 (3단계에서 전적 저장소를 붙인다).

## 10. 세부 도구 (구현자 판단, 사용자 확인용으로 기록)

- **Socket.IO**: 서버와 화면이 실시간으로 주고받게 해 주는 도구. 접속 확인("살아 있니?"), 끊긴 뒤 다시 접속, 방 단위로 보내기를 기본으로 해 준다.
- 서버는 같은 저장소(`server/` 폴더)에 두고 JavaScript로 쓴다.
- **호스팅**: Render 같은 무료 Node.js 호스팅을 우선 검토한다. 무료 조건은 자주 바뀌므로, 올리기 전에 최신 조건을 확인하고 사용자에게 확인받는다. 서버가 잠들어 있을 때 화면에는 "서버를 깨우는 중…"을 보여 준다.

## 11. 확인 방법

- `bot.js`, 빠른대전 줄(시간을 가짜 시계로 돌려서), 친선대전 방, 게임 한 판 처리는 자동 테스트로 확인한다.
- 내 컴퓨터에서 서버를 켜고 브라우저 창 여러 개로 실제 접속해 끝까지 해 본다:
  (창마다 `?player=` 설정으로 다른 사람처럼 접속)
  빠른대전 2명(+컴퓨터 2), 혼자 "컴퓨터와 바로 하기", 친선대전 2·3·4명, 게임 중 창 닫았다 다시 열기(이어하기/나가기),
  "게임 나가기" 버튼, 30초 동안 아무것도 안 하기.
- 30초 시간 제한과 접속 확인은 가짜 시계로 테스트해서 실제로 기다리지 않는다.
- 컴퓨터끼리만 두는 판을 많이 돌려서 멈추거나 오류가 나지 않는지 확인한다.

## 12. 구현자에게 맡긴 것

- 접속 확인 간격, 초대코드 길이(4~6자), 메시지 형식, 화면 배치와 꾸밈
- 테스트 방법의 세부, 폴더 안 파일 나누기의 세부
