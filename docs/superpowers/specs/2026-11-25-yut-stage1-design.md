# 웹 윷놀이 1단계 설계 문서

작성일: 2026-11-25
원본 요구사항: 프로젝트 루트의 `CLAUDE.md` (사용자가 작성한 명세서)

## 1. 목적과 이유

- 웹 브라우저 한 화면에서 2~4명이 번갈아 하는 개인전 윷놀이를 만든다.
- 이번 1단계의 핵심은 **규칙을 명세대로 정확하게 구현하는 것**이다.
  특히 "완주 대기"와 빽도 처리가 가장 중요하다.
- 나중에 2단계(대기실, 온라인 멀티플레이)와 3단계(전적, 승률)로 확장하기 쉽도록
  **규칙 코드와 화면 코드를 완전히 분리**한다.
- 개발자는 코딩 초보다. 코드에는 한국어 주석을 달고, 구조는 단순하게 유지한다.

## 2. 목표 / 비목표 / 실패 조건

**목표 (1단계 완료 조건, 명세서 그대로)**
- 모든 규칙이 명세서대로 동작한다.
- 2명, 3명, 4명 플레이를 각각 끝까지 진행할 수 있다.
- 빽도의 모든 상황(출발 전, 첫 칸, 지름길 위)에서 오류 없이 처리된다.
- 출발점에 정확히 도착하면 완주가 아니고, 더 높은 수가 나와야 완주된다.
- 완주 대기 후 "상대가 잡음"과 "내 다음 턴에 어떤 결과로든 완주" 두 경우가 모두 동작한다.
- 승리하면 우승자가 화면에 표시된다.

**비목표 (만들지 않는 것)**
- 온라인 접속, 대기실, 로그인, 전적 저장, 효과음, 모바일 최적화
- 2등 이하 순위 계산 (첫 우승자가 나오면 게임 종료)
- 되돌리기(undo), 저장 후 이어하기, 컴퓨터 상대(AI)

**실패로 보는 것 (기능은 돌아가도 실패)**
- 규칙 코드 안에 React나 화면 관련 코드가 섞여 있어서 2단계에서 서버로 옮길 수 없는 경우
- 규칙 판정이 화면 코드 쪽에 흩어져 있는 경우

## 3. 확정된 결정 사항

| 항목 | 결정 | 결정한 사람 |
|---|---|---|
| 추가로 던진 결과 | **모아서 사용**: 던질 것을 모두 던진 뒤, 모인 결과를 원하는 순서대로 원하는 말에 하나씩 쓴다 | 사용자 |
| 만드는 방식 | **React** 사용 (방식 B) | 사용자 |
| 빽도 세부 규칙 | 명세서의 기본값을 그대로 따른다 | 사용자 |
| 빽도 순서 | 말이 없을 때 나온 빽도도, 같은 턴에 다른 결과로 말을 먼저 꺼내면 그 뒤에 쓸 수 있다 | 사용자 |
| 같은 턴 완주 | 완주 대기가 된 말을 **같은 턴의 남은 결과로도** 바로 완주시킬 수 있다 | 사용자 |
| 지름길 | 모서리(5, 10)에서 이동을 시작할 때 **지름길/바깥길 중 선택**한다. 중앙(22)은 자동으로 출구 방향 | 사용자 |
| 낙 (추가) | 던질 때마다 약 5%. 낙이면 더 못 던진다. 모은 결과가 있으면 그것만 쓰고 차례 종료, 없으면 차례를 건너뜀 | 사용자 |
| 윷 던지기 화면 (추가) | 멍석 위 윷가락 4개가 약 0.9초 굴러가다 멈추고 결과 글자가 뜬다. 낙이면 가락 하나가 멍석 밖에 놓인다 | 사용자 |
| 대기 공간 (추가) | 윷판 아래에 플레이어별 대기 공간. 출발 전 말을 여기서 눌러 꺼낸다. 완주한 말은 ✓, 완주 대기는 표시 | 사용자 |

## 4. 만드는 방식 (검토한 접근법)

| 방식 | 장점 | 단점 | 결과 |
|---|---|---|---|
| A. HTML + CSS + 자바스크립트만 사용 | 설치할 것이 없고 배울 것이 적다 | 화면이 복잡해지면 코드가 길어진다 | 선택 안 함 |
| **B. React (Vite로 프로젝트 구성)** | 화면을 부품(컴포넌트)으로 나누기 좋고, 2단계에서 화면이 늘어나도 정리하기 쉽다 | 설치와 설정이 필요하고, 배울 개념이 늘어난다 | **사용자 선택** |

세부 도구 (구현자 판단, 사용자 확인용으로 기록):
- **Vite**: React 프로젝트를 만들고 실행해 주는 도구. `npm run dev` 한 줄로 실행한다.
- **JavaScript** 사용 (TypeScript는 쓰지 않는다. 초보자에게 부담을 줄이기 위함).
- **Vitest**: 규칙 코드를 자동으로 검사하는 테스트 도구. Vite와 함께 쓰기 쉽다.
- 화면 꾸미기는 일반 CSS 파일로 한다. 추가 디자인 라이브러리는 쓰지 않는다.

**제약 조건 (최종 목표 관련)**
- 최종적으로 여러 사람이 만든 게임을 한 웹사이트(게임 모음 페이지)에 합친다.
  각 게임은 자기 폴더(예: `/games/yut/`)에 들어가고, 메인 페이지에서 링크나 iframe으로 연다.
- 그래서 빌드 결과물은 **서버 없이 열리는 정적 파일**이어야 하고,
  어느 폴더에 넣어도 동작하도록 **상대 경로**를 쓴다 (Vite 설정 `base: './'`).
- 로그인과 전적은 나중에 메인 사이트가 관리할 가능성이 높다. 1단계에서는 아무것도 만들지 않지만,
  게임 결과(우승자)를 규칙 코드의 상태에서 쉽게 꺼낼 수 있게 둔다.

## 5. 폴더 구조

```
src/
  rules/          ← 규칙 계산 전용. React를 절대 import하지 않는다.
    board.js      ← 윷판 칸 번호, 연결 관계, 다음 칸 계산
    yut.js        ← 윷 던지기 (랜덤)
    game.js       ← 게임 상태 만들기, 가능한 이동 계산, 이동 적용, 턴 진행
  rules/__tests__/← 규칙 자동 검사 (Vitest)
  ui/             ← 화면 전용. 규칙 판단은 직접 하지 않고 rules/의 함수를 부른다.
    SetupScreen.jsx   ← 인원(2~4명)과 이름 입력
    GameScreen.jsx    ← 윷판 + 플레이어 정보 + 던지기 영역
    Board.jsx         ← 윷판과 말 그리기 (SVG)
    ResultScreen.jsx  ← 우승자 표시
  App.jsx         ← 화면 전환 (시작 → 게임 → 결과)
```

**규칙 코드의 원칙**
- 게임 상태는 평범한 자바스크립트 객체 하나로 표현한다 (JSON으로 그대로 바꿀 수 있어야 함).
  → 2단계에서 이 상태를 서버로 보내거나 받기만 하면 된다.
- 규칙 함수는 "현재 상태 + 행동"을 받아 "새 상태"를 돌려준다. 원래 상태는 바꾸지 않는다.
- 랜덤은 함수 인자로 받는다 (테스트에서 원하는 결과를 강제로 넣기 위함).

주요 함수 (이름은 구현자가 다듬어도 됨):
- `createGame(playerNames)` → 새 게임 상태
- `throwYut(state, random)` → 던진 결과를 모음에 추가한 새 상태
- `getLegalMoves(state)` → 지금 할 수 있는 이동 목록 (어떤 결과를, 어떤 말에)
- `applyMove(state, move)` → 이동, 잡기, 업기, 완주를 처리한 새 상태
- `passUnusable(state)` → 쓸 수 없는 결과를 버리고 턴을 넘김

## 6. 윷판 모델

칸 번호 (총 29칸):

```
 10  9  8  7  6  5
 11 25        20  4
 12   26    21    3
          22         (22 = 중앙)
 13   23    27    2
 14 24        28  1
 15 16 17 18 19  0     (0 = 출발점 = 도착점)
```

- 바깥 길: 0 → 1 → … → 19 → 0 (반시계 방향)
- 모서리 5 지름길: 5 → 20 → 21 → 22(중앙) → 23 → 24 → 15
- 모서리 10 지름길: 10 → 25 → 26 → 22(중앙) → 27 → 28 → 0
- 중앙 출구: 22 → 27 → 28 → 0

**다음 칸 정하는 규칙** (말이 이동을 "시작하는" 칸 기준):
- 5에서 이동을 시작하면 플레이어가 고른다: 지름길(20으로) 또는 바깥길(6으로).
- 10에서 이동을 시작하면 플레이어가 고른다: 지름길(25로) 또는 바깥길(11로).
- 22(중앙)에서 이동을 시작하면 자동으로 27로 간다 (출구 방향, 선택 없음).
- 이동 중에 22를 지나가는 경우: 21에서 왔으면 23으로, 26에서 왔으면 27로 간다.
- 15는 지름길이 없다. 그냥 16으로 간다.
- 이동 중에 5나 10을 지나가기만 하면 바깥길로 계속 간다 (멈춰야 지름길 선택 가능).
- 그 외에는 위 길을 따라간다.
- 빽도는 길 선택이 없다 (아래 참고).

따라서 "이동" 하나는 (어떤 결과, 어떤 말, 모서리라면 어느 길)로 정해진다.
모서리에 있는 말에 결과 하나를 쓰면 가능한 이동이 두 개(지름길/바깥길)가 된다.

**빽도(뒤로 1칸)**: 말마다 "지나온 칸 기록"을 저장해 두고, 빽도를 쓰면 바로 이전 칸으로 돌아간다.
이렇게 하면 지름길 위에서도 온 길을 따라 되돌아간다 (예: 24에서 빽도 → 23, 15에서 빽도 → 24 또는 14, 온 길에 따라).
빽도로 모서리(5, 10)에 도착하면, 그다음 이동에서 다시 길을 고를 수 있다. 빽도로 중앙에 도착하면 그다음 이동은 출구 방향이다.

**남은 칸 수**: 말의 현재 칸에서 위 규칙대로 한 칸씩 따라가 0에 닿을 때까지 센다.
모서리에서는 고른 길에 따라 남은 칸 수가 달라지므로, 길마다 따로 계산한다.
- 던진 수 > 남은 칸 수 → 완주
- 던진 수 = 남은 칸 수 → 출발점(0)에 멈춤 → **완주 대기**
- 던진 수 < 남은 칸 수 → 그만큼 이동

## 7. 말의 상태

각 말은 다음 중 하나다:
- **출발 전**: 아직 판에 나오지 않음
- **판 위**: 1~28번 칸 중 하나에 있음
- **완주 대기**: 0번 칸에 머묾 (화면에 "완주 대기 중" 표시)
- **완주**: 게임에서 빠짐

업은 말은 같은 칸의 같은 플레이어 말들로 자연스럽게 표현한다 (같은 칸 = 업힘).
업힌 말들은 함께 이동하고, 함께 잡히고, 함께 완주 대기가 되고, 함께 완주한다.
업을 때 지나온 칸 기록은 **도착한 말(움직인 쪽)의 기록**을 함께 쓴다 (구현자 판단).

## 8. 턴 진행 (모아서 사용 방식)

1. **던지기 단계**: 현재 플레이어가 "윷 던지기" 버튼을 누른다. 결과가 모음에 추가된다.
   윷이나 모면 다시 던지기 단계. 그 외에는 이동 단계로 넘어간다.
2. **이동 단계**: 모음에서 결과 하나와 움직일 말(또는 새 말 꺼내기)을 고른다.
   - 상대 말을 잡으면 → 남은 결과는 그대로 두고, **던지기 단계로 한 번 더** 돌아간다.
   - 모음이 비면 → 턴 종료, 다음 플레이어.
   - 남은 결과 중 쓸 수 있는 것이 하나도 없으면 → 버리고 턴 종료 (화면에 이유 표시).
3. 쓸 수 있는 결과가 있으면 반드시 써야 한다 (건너뛰기 없음).
4. 말 4개가 모두 완주하는 순간 게임이 끝나고 결과 화면으로 간다.

## 9. 빽도 세부 규칙 (명세서 기본값)

- 빽도는 추가 턴이 없다.
- 출발 전 말은 빽도로 움직일 수 없다.
- 판 위(완주 대기 포함)에 내 말이 하나도 없으면 빽도는 쓸 수 없는 결과로 버려진다.
  모아서 사용 방식이므로, 같은 턴에 다른 결과로 말을 먼저 꺼낸 뒤에는 빽도를 쓸 수 있다.
- 1번 칸에서 빽도 → 0번 칸으로 가서 완주 대기.
- 지름길 위에서 빽도 → 온 길을 따라 한 칸 뒤로.
- 빽도로 간 칸에 상대 말이 있으면 잡는다 (추가 던지기 있음). 0번 칸의 완주 대기 말도 마찬가지.

## 10. 잡기와 완주 대기

- 내 말이 상대 말이 있는 칸에 **멈추면** 그 칸의 상대 말을 모두 잡는다. 지나가는 것은 잡지 않는다.
- 잡힌 말은 출발 전 상태로 돌아간다.
- 0번 칸에 정확히 도착하면 그곳의 상대 완주 대기 말을 잡고, 내 말이 완주 대기가 된다.
  0번 칸을 지나쳐 완주하는 말은 잡지 않는다.
- 완주 대기 말은 어떤 결과(빽도 포함) 하나를 써서 완주시킬 수 있다.
  다음 턴뿐 아니라, 완주 대기가 된 **그 턴의 남은 결과**로도 바로 완주시킬 수 있다.
  (완주 대기 말에 결과를 쓸지, 다른 말에 쓸지는 플레이어가 고른다.)
- 내 말이 있는 칸에 내 말이 도착하면 업는다 (0번 칸 포함).

## 11. 윷 던지기 확률

실제 윷가락 4개를 흉내 낸다 (구현자 판단): 각 가락이 앞/뒤가 나올 확률 1/2, 한 가락에 빽도 표시.
- 먼저 약 5% 확률로 낙 (가락 하나가 판 밖으로)
- 낙이 아니면: 빽도 1/16, 도 3/16, 개 6/16, 걸 4/16, 윷 1/16, 모 1/16

## 12. 화면

```
[시작 화면]  인원 선택(2/3/4) → 이름 입력 → 시작

[게임 화면]
 ┌────────────────────┐  ┌─────────────────────┐
 │                    │  │ 지금 차례: 철수 (빨강) │
 │      윷판 (SVG)     │  │ [윷 던지기]           │
 │  말은 플레이어 색   │  │ 모인 결과: 모 윷 개    │
 │  업힌 말은 숫자 표시 │  │ 결과를 고른 뒤 말 클릭  │
 │                    │  │                     │
 └────────────────────┘  │ 플레이어별:            │
                          │  출발 전 ●● 완주 ●    │
                          │  완주 대기 중 표시     │
                          └─────────────────────┘
[결과 화면]  "철수 우승!" + 다시 하기 버튼
```

- 플레이어 색: 빨강, 파랑, 초록, 노랑.
- 결과를 고르면, 그 결과로 움직일 수 있는 말이 강조되고, 도착할 칸이 미리 표시된다.
- 모서리(5, 10)에 있는 말을 고르면 도착할 칸이 두 군데(지름길/바깥길) 표시되고, 그중 하나를 클릭해 고른다.
- 출발 전 말은 판 옆 대기 영역에 있고, 클릭하면 새 말을 꺼낸다.
- 완주 대기 말은 0번 칸 옆에 "완주 대기 중" 글자로 표시한다.

## 13. 테스트 계획

규칙은 Vitest로 자동 검사한다. 랜덤 대신 정해진 결과를 넣어 아래 상황을 모두 확인한다.
- 바깥 길 / 5번 지름길 / 10번 지름길 / 중앙 출구 / 중앙 통과 이동
- 모서리에서 지름길과 바깥길 두 이동이 모두 나오고, 각각 남은 칸 수가 맞게 계산됨
- 같은 턴 안에서 완주 대기가 된 말을 남은 결과로 완주
- 빽도: 출발 전만 있을 때 버려짐, 1번 칸 → 완주 대기, 지름길 위에서 온 길로, 빽도 잡기
- 정확히 도착 → 완주 대기, 넘치는 수 → 완주, 적은 수 → 이동
- 완주 대기 말이 다음 턴에 빽도로 완주, 상대가 0번에 정확히 도착해 잡음
- 업기, 업힌 말 함께 잡힘, 함께 완주 대기, 함께 완주
- 윷/모 연속 던지기, 잡은 뒤 추가 던지기, 쓸 수 없는 결과 버리기
- 4개 완주 시 승리
화면은 직접 실행해서 2명, 3명, 4명 게임을 끝까지 해 본다.
